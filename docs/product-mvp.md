# 宠物社区（首版 MVP）产品方案

> 面向：产品经理验收用。看这一页就能知道"第一版做了什么、不做什么、怎么算做完"。
> 版本：v0.1（首版范围）　维护：Lead

## 1. 一句话定位

一个让养宠人**晒宠物、看经验、查养宠知识**的中文垂直社区。首版不追求功能多，追求"打开就像个真产品"。

## 2. 目标用户与核心场景

| 用户 | 场景 | 首版满足方式 |
| --- | --- | --- |
| 养宠新手 | 不知道猫狗怎么喂、怎么养 | 养宠百科（分类文章） |
| 爱晒宠的年轻用户 | 想发照片、秀自家主子 | 发帖 + 社区信息流 |
| 正在做养宠决策的人 | 看别人真实经验 | 帖子列表按分类筛选 + 详情 + 点赞 |

## 3. 首版做什么（5 个页面 + 1 套接口）

1. **首页**：品牌头、分类快捷入口、热门帖子卡片流、百科推荐区
2. **帖子列表**：按分类（猫/狗/异宠/健康/喂养/行为）筛选、分页加载、空状态
3. **帖子详情**：正文、评论列表、点赞按钮（点赞后数字实时变化）
4. **发布帖子**：标题/分类/正文/昵称，必填校验，发布成功后跳到新帖详情
5. **养宠百科**：文章列表 + 文章详情

配套后端接口 8 个（健康检查、分类、帖子列表/详情/发布/点赞、百科列表/详情），数据落在本地数据库，附带 20 条帖子、10 篇百科的种子内容。

## 4. 首版明确不做（避免范围膨胀）

- 用户注册登录、权限体系（首版用"昵称"代替账号）
- 图片真实上传（用图片链接/占位图）
- 评论发布（只展示已有评论）
- 支付、商城、服务预约
- 消息通知、私信、关注关系
- 部署上线（首版本机可运行即可）

> 这些都在第 2、3 版路线里，等首版验收通过再加。

## 5. 主验收流程（PM 自己就能点）

```
打开首页 → 点分类 → 进帖子详情 → 点个赞（数字 +1）→ 回列表
→ 发布一条新帖 → 自动跳到详情 → 回列表能看到刚发的帖
→ 进百科列表 → 打开一篇文章
```

全部走通、页面无报错，即视为首版验收通过。

## 6. 团队与分工

| 角色 | 负责 |
| --- | --- |
| Lead（我） | 产品方案、任务拆分、进度跟踪、最终验收 |
| architect 技术负责人 | 工程骨架、技术选型、一条命令启动、联调收口 |
| frontend-dev 前端工程师 | 5 个页面、交互、视觉风格 |
| backend-dev 后端工程师 | 8 个接口、数据库与种子数据、接口文档 |

## 7. 后续版本建议（等你拍板）

- **v1.1**：注册登录、发帖带图、评论发布
- **v1.2**：搜索、话题标签、关注与消息
- **v2.0**：商城 or 服务预约（二选一，别同时做）

## 8. 需要你（PM）确认的三个产品问题

1. 网站叫什么名字？（暂用"宠物社区"，有名字我让前端换）
2. 分类够不够？现在：猫、狗、异宠、健康、喂养、行为
3. 首版验收通过后，下一版优先做"登录+发图"还是"搜索"？
